# 自行车维修工单长图

## 何时使用

- 用户说：生成工单、长图、横条图、合并长图
- 用户提供多张维修照片，要求收费标注、品牌名、祝福语或时间信息
- 用户要求按参考图样式排版（2400 宽横条 + 米色底）

## 输出规格

### 单组横条（一张工单）

| 项目 | 规格 |
|------|------|
| 画布宽度 | **2400 px** |
| 照片区高度 | **640 px** |
| 照片排列 | 从左到右横排，**2 px 白色分隔线** |
| 背景色 | `(245, 241, 232)` 米色 |
| 底部区高度 | **180 px**（含祝福语时） |

### 单张横条结构

```
┌──────────────────────────────────────────────┐
│ [品牌标注-白字左上]  [图1│图2│…│图N]          │
│                      最后一张右下角：收费：XX  │
├──────────────────────────────────────────────┤
│              祝福语（红色，右对齐）            │
└──────────────────────────────────────────────┘
```

### 多组合并长图

- 多张已生成的 **2400×820** 横条 **从上至下拼接，不裁剪**
- 三张宽度必须一致（均为 2400）；禁止用低分辨率截图放大替代，应重新生成
- 最底部单独加 **黑色时间区**（无祝福语）
- 输出另存为新文件名（如 `维修工单长图_合并.jpg`），避免覆盖旧版

## 文字规则（必须遵守）

完整规则见 [reference/图片长图文本规则.md](reference/图片长图文本规则.md)。核心要点：

### 收费标注

- 文案逐字使用用户指定内容，例如：`收费：20（首单）`、`收费：25`
- **红色** `(220, 35, 30)`，白描边，仅写在 **最后一张照片右下角**
- 按文字实际宽度靠右对齐；格窄时自动缩小字号（40→24），确保「收费」不被裁切
- 用户要求删除「（第二单）」等括号内容时，只改文案，不改位置逻辑

### 品牌标注

- 用户指定品牌名，写在 **整组横条左上角**
- **白色** `(255, 255, 255)`，字号 48，细黑描边 `(30, 30, 30)` 保证可读
- 示例：`马吉斯high road`、`cadex`、`倍耐力rs`

### 祝福语（单组横条）

- 仅当用户需要时添加；合并长图若用户说「不需要祝福语」则不加
- 默认两句（红色，右对齐）：
  - 祝老板早日骑到300瓦！
  - 一路顺风，功率拉满，越骑越强！
- 可加 `—··` / `··` 装饰，不遮挡收费与照片主体

### 时间信息（合并长图底部）

- 用户指定才写；格式完整：`2026年8月31日 12:25:00`
- 三行黑色左对齐：
  - `收货时间：`（用户说收货则用收货，说收到则用收到）
  - `完成时间：`
  - `耗时：`
- **跨日耗时用「天+小时」**：如 `1天2小时`（分钟≥30 则小时进位）
- 只有用户说「以当前时间为准」才读取系统时间

### 画质边界

- 使用 **真实原图** Pillow 合成
- 只处理文字、分隔线、画布；**禁止** AI 重绘、风格化、整体模糊
- 手机截图仅去掉顶部时间栏（11.5%）和底部进度条（17.5%），再取中心方形

## 工作流程

### 1. 确认输入

向用户确认（缺失则用合理默认或追问）：

- 照片文件列表与顺序
- 每组收费文案
- 每组品牌标注（可选）
- 是否要祝福语
- 是否合并；若合并：收货/完成时间

### 2. 生成单组横条

```bash
python3 .cursor/skills/bike-repair-work-order-banner/scripts/generate_work_order_long_image.py
```

运行前在脚本或调用代码中设置：

- `PHOTO_FILES`：assets 目录下文件名列表
- `FEE_TEXT`：如 `收费：20（首单）`
- `BRAND_LABEL`：如 `马吉斯high road`（无则留空）
- `OUTPUT`：输出路径
- `ASSETS`：用户上传图片目录

### 3. 合并多组（可选）

```bash
python3 .cursor/skills/bike-repair-work-order-banner/scripts/generate_merged_long_image.py
```

设置：

- `IMAGE_FILES`：各横条 JPG 路径（必须同为 2400 宽）
- `RECEIVED_AT` / `COMPLETED_AT`
- `OUTPUT`：合并结果路径

### 4. 批量生成示例

参考 [scripts/regenerate_all_banners.py](scripts/regenerate_all_banners.py)，按数组配置多组 `photos / fee / label / output` 后依次生成再合并。

### 5. 交付前检查

- [ ] 收费完整显示（含「收费」二字）
- [ ] 品牌标注在左上、白色
- [ ] 三张合并图宽度均为 2400
- [ ] 时间格式完整，耗时为天+小时
- [ ] 输出文件名为用户可识别的新文件（`_合并.jpg` / `_最新.jpg`）
- [ ] 未擅自添加用户未要求的水印、取件码

## 常见错误

| 问题 | 原因 | 处理 |
|------|------|------|
| 用户看到旧图 | 打开了 `维修工单长图.jpg` 旧文件 | 交付 `_合并.jpg` 或 `_最新.jpg` |
| 「收费」被裁切 | 照片过多、格太窄 | 自动缩小字号或减照片数 |
| 最下图与上面对不齐 | 用了 1920 截图 | 重新生成 2400 横条再合并 |
| 用户不要祝福语 | 合并时重复加了 | 合并脚本底部只保留时间 |

## 参考样式

- 横条：照片横排 + 末图右下角红色收费 + 米色底祝福语
- 合并：三组横条竖拼 + 最底黑色收货/完成/耗时
- 参考成品见用户提供的 `维修工单长图_合并` 截图
